# PicGenTool 质量与发布优化设计

## 意图与背景

PicGenTool 已具备 1～30 张图片并发预处理、Word 模板导出、协作式取消、单实例 IPC、Windows 右键菜单和 PyInstaller one-dir 发布能力。本轮在保持现有生成结果和操作主流程的前提下，补齐手机图片兼容性、输入确定性、故障恢复、自诊断、轻量交互反馈以及可验证的 Windows 发布链路。

这批改动面向日常使用该桌面工具的 Windows 用户，也面向维护发布包的开发者。成功标准不是单纯增加入口，而是让常见输入、异常、移动安装目录和无签名凭据等情况都有确定行为，并且 CI 能证明核心路径没有回归。

## 目标

- 支持 `.heic`、`.heif` 图片，并沿用现有 EXIF 方向、裁剪、缩放和 JPEG 输出流程。
- 对内容完全一致的图片去重，保持首次出现的顺序，并向用户说明跳过数量。
- 日志按大小轮转，保留足够诊断信息且不记录标题、地点和完整图片路径。
- 已注册右键菜单的用户移动或更新程序后，启动新程序一次即可自动修复命令路径。
- CI 在打包发布前执行 Python 3.11/3.12 测试、语法检查和模板完整性检查。
- 未捕获的主线程和后台线程异常统一记录，并显示不泄露私人路径的恢复提示。
- 校验 `Template-1.docx` 至 `Template-30.docx` 的文件、DOCX ZIP 结构和占位符集合。
- 建立可重复的打包体积报告和预算，在加入 HEIC 解码器后仍能解释体积变化。
- 让模板打开阶段与图片处理阶段重叠，同时不跨线程并发操作 docxtpl/python-docx 对象。
- 记住上次标题、地点、日期、复选框和最近目录，不恢复照片列表。
- 拖入支持的图片时显示即时高亮和文字反馈，离开或放下后可靠恢复。
- 提供“关于 / 诊断”入口，可查看版本、运行环境、模板、HEIF、日志和右键菜单状态，并复制诊断文本。
- 提供凭据外置、可选执行且可验证的 Windows Authenticode 签名步骤。

## 非目标与反目标

- 不实现感知哈希或“视觉相似”去重，避免误删连拍或构图相似照片。
- 不恢复上次选择的照片路径，不保存图片内容或生成历史。
- 不取消 30 个模板，不直接改写 DOCX XML生成文档。
- 不把 Word 渲染和保存拆到多个线程，不共享正在使用的 `DocxTemplate` 对象。
- 不把证书、私钥、PFX、密码或 Base64 证书内容写入仓库、日志或构建产物。
- 不为追求最小体积删除 Qt 软件渲染等关键兼容组件，也不切换到启动更慢的 one-file。
- 不在这轮重做窗口视觉体系或迁移为 `QMainWindow`。

## 约束

- 最低 Python 版本保持 3.11；CI 同时覆盖 3.11 和 3.12。
- 图片上限保持 30 张，输出保持 6.4 cm × 4.8 cm、240 DPI、JPEG 质量 60。
- 保持 PyQt6、Pillow、docxtpl、python-docx 和 PyInstaller one-dir 技术栈。
- HEIC/HEIF 使用 `pi-heif==1.4.0`（pillow-heif 同项目的解码专用发行版），支持 Pillow 12.2、Python 3.11/3.12，并提供 Windows CPython wheels。1.9.0 要求 Pillow>=13；完整 1.8.1 wheel 会引入静态依赖 libx265，超过本轮体积预算。本应用只需 HEIF 解码，之后仍统一保存 JPEG。
- 去重按 SHA-256 文件内容定义，路径比较使用 Windows 不区分大小写的规范键；首次出现优先。
- 日志默认单文件上限 5 MiB、保留 3 个备份。
- 模板完整性规则固定为 1～30 号文件，每个模板含 `title`、`location`、`dateForDoc` 和恰好 `image1`～`imageN`。
- 打包基线为当前本地 901 个文件、119.01 MiB；加入 HEIF 后设 130 MiB 警戒预算，超过时 CI 报错并输出最大文件列表。
- 所有错误对话框使用通用说明；详细堆栈只进入日志。

## 方案比较

### 方案 A：现有分层内增量增强（采用）

保留 `ui → services → models` 结构，为设置、诊断、异常和 Windows 资源管理增加小型模块；核心生成服务只扩展明确接口。优点是改动可逐项测试、回归面小，并能复用上一轮性能和取消设计。代价是会增加数个职责单一的文件。

### 方案 B：通用任务图和插件式流水线

把图片处理、模板准备、Word 导出、打开文件建模为任务节点，并用统一调度器管理并发。扩展性强，但对最多 30 张图片的单用途工具过重，也会扩大取消和进度语义的回归范围。

### 方案 C：发布能力优先、功能后补

先落 CI、签名和体积预算，再补输入与可靠性。发布链路能更快改进，但会把未覆盖的 HEIC、重复输入和异常行为带入新发布包，不符合“先保证行为、再发布”的顺序。

## 总体结构

```text
文件选择 / 拖拽 / IPC / 右键菜单
                │
                ▼
       ImageService 过滤 + 内容去重
                │
                ▼
 GenerationWorker ───────────────┐
   │                              │
   │ 图片准备（后台 future，内部线程池）│ Word 模板打开（Worker 线程）
   └──────────────┬───────────────┘
                  ▼
          同一 Worker 线程渲染和保存
                  │
                  ▼
             原子替换 DOCX

启动检查 → 模板摘要 / 右键菜单自愈 / 全局异常钩子
诊断入口 → 版本、HEIF、模板、日志、注册状态、打包状态
发布链路 → 测试 → 打包 → 体积预算 → 可选签名 → 验签 → 压缩发布
```

## 详细设计

### HEIC/HEIF 支持

`config.SUPPORTED_FORMATS` 增加 `.heic` 和 `.heif`。`ImageService` 在第一次解码 HEIF 时调用 `pi_heif.register_heif_opener()`，之后继续使用现有 `PIL.Image.open()` 路径。选择对话框、CLI、IPC、拖拽和右键菜单都复用同一扩展名集合。

测试使用仓库内带 SHA-256 断言的固定 HEIC/HEIF 二进制样本，再走完整图片准备流程，断言输出 JPEG 的尺寸、RGB 模式和数量。损坏的 HEIC 仍映射为不暴露目录的“无法识别/解码失败”错误。

### 重复图片去重

新增结果对象 `DeduplicationResult(paths, duplicate_count, failures)`。先用规范化路径键排除同一路径，再按文件大小分组并流式计算 SHA-256，只有内容完全一致才判重。保留首次出现顺序；现有列表和新选择一起参与比较。

哈希工作通过专用图片导入线程执行，窗口和表单保持响应；同一时刻串行处理一批导入请求，拖拽、文件选择和 IPC 到达的新批次排队，避免两个结果基于相同旧快照竞争。最大数量校验在去重之后执行。添加成功时状态显示“已添加 N 张，跳过 M 张重复图片”；如果全是重复项，不弹错误，只显示“未添加：M 张图片已存在”。单个无法读取的文件记录安全文件名并报告，其他可读文件继续参与去重和添加；若可读唯一项超过剩余上限，则该批可读项整体不添加。

### Word 与图片阶段重叠

`WordExporter.prepare(payload_without_images)` 在 `GenerationWorker` 所在线程打开模板并创建只属于该线程的准备对象。与此同时，`ImageService.prepare_images()` 在一个编排 future 中执行，其内部仍使用现有最多 4 个单图线程。

准备对象只在创建它的 Worker 线程中用于 `InlineImage`、render 和 save；图片 future 只返回路径。任何一侧失败都取消令牌、等待另一侧安全结束并清理临时图片。进度区间调整为图片 0～60、模板准备 10～20（与图片进度取单调最大值）、布局 65、导出 82～100。

### 日志轮转与全局异常

把 `FileHandler` 替换为 `RotatingFileHandler(maxBytes=5*1024*1024, backupCount=3, encoding="utf-8")`，保留用户数据目录优先、临时目录回退的行为，并提供当前日志路径查询。

全局异常处理器安装 `sys.excepthook` 和 `threading.excepthook`。它先用当前任务登记的标题、地点、图片路径、输出路径以及用户目录对格式化后的堆栈做字符串脱敏，再记录完整结构和已脱敏文本；未登记的任意第三方字符串不承诺语义识别。处理器通过 Qt 信号在 UI 线程显示通用对话框，并给出“可在关于 / 诊断中复制信息”的恢复路径。`KeyboardInterrupt`、`SystemExit` 保持系统语义；异常处理器自身失败时回退到原始 hook，防止递归。Worker 开始任务时登记敏感值，结束时清除。

### 模板完整性自检

`TemplateService.validate_all(deep: bool)` 返回结构化结果。轻量模式检查 1～30 是否存在；深度模式还用 `zipfile.ZipFile` 验证 ZIP、`word/document.xml` 和占位符集合。启动后执行轻量检查：失败时状态区提示并禁止生成；诊断窗口和 CI 执行深度检查并展示具体模板编号和原因。

模板内容来自项目自身，但仍只读取 ZIP 成员，不执行其中任何宏或外部关系。

### 右键菜单路径自愈

把注册命令构造和状态检查提取到 `services/explorer_integration.py`，工具脚本改为调用该服务。状态分为 `unsupported`、`not_registered`、`current`、`stale` 和 `partial`。

应用仅在 Windows 打包态且检测到既有 PicGenTool 注册项时修复，不为从未选择该功能的用户自动创建菜单。修复覆盖所有支持扩展名（含 HEIC/HEIF），命令目标使用当前 `sys.executable`。应用移动后，用户从新位置启动一次即可更新注册表；诊断窗口显示结果。

### 设置持久化

使用 `QSettings("PicGenTool", "PicGenToolDesktop")` 保存标题、地点、日期、生成后打开、窗口置顶和最近图片目录。启动恢复有效值；日期超出控件范围时回退今天；最近目录不存在时回退默认目录。

关闭窗口和开始生成前保存。生成成功后清除标题和照片，保留地点、日期和复选框以便连续制作；用户明确点击“清空内容”时，标题、地点、日期恢复默认值并立即持久化，复选框偏好仍保留。永不保存图片列表、输出路径或诊断复制内容。

### 拖拽反馈和诊断入口

拖入含支持图片的 URL 时，`status_card` 设置动态属性 `dragActive=true`，使用蓝色边框和浅色背景，同时状态文字改为“松开即可添加图片”；拖离、拒绝和放下都统一清理属性并恢复真实状态。现有“选择照片”按钮继续作为键盘和单指替代入口。

主按钮行增加次要按钮“关于 / 诊断”，视觉权重低于“生成文档”。诊断对话框使用只读文本区和带文字的“复制诊断”“打开日志目录”“关闭”按钮；复制成功显示短暂、完整的状态文字，不抢夺焦点。所有新控件设置可访问名称并加入合理 Tab 顺序。

### CI、体积和签名

GitHub Actions 增加独立 `test` job，在 Python 3.11/3.12 Windows 矩阵安装运行与开发依赖，执行 `compileall`、全量 pytest 和深度模板检查。`build` 依赖 `test`。

新增 `tools/package_report.py`，输出文件数、总 MiB、按顶层目录汇总和最大文件，并支持 `--max-mib 130`。`pgt.spec` 移除重复的 `config.py` data，排除确认未使用的 Qt PDF 与 Pillow AVIF 插件，但保留软件 OpenGL；构建后运行包内 HEIF/模板/启动烟测，再执行体积预算。

签名步骤仅签应用自有的 `dist/PGT/PGT.exe`，不重签 Python、Qt、Pillow 等第三方 DLL。仅在 `WINDOWS_CERTIFICATE_BASE64` 和 `WINDOWS_CERTIFICATE_PASSWORD` 均存在时运行：将证书写入 runner 临时目录，用 `SecureString` 导入临时 runner 的 `CurrentUser\My` 证书存储，再按 thumbprint 调用 `signtool sign /fd SHA256 /tr <RFC3161 URL> /td SHA256`，随后 `signtool verify /pa /tw`。时间戳 URL 由 `WINDOWS_TIMESTAMP_URL` 配置，缺省为 Microsoft 文档示例 `http://timestamp.digicert.com`。`finally` 中无条件移除导入的证书和临时 PFX，避免把密码作为 SignTool 命令行参数。无凭据时明确记录“跳过签名”，测试和打包仍可运行；发布说明应区分签名与未签名产物。

## 错误处理与隐私

- 图片错误只包含源文件名，不包含父目录。
- 诊断文本默认包含日志目录但不包含标题、地点、图片路径、输出路径和注册表命令中的用户目录；复制时对当前可执行文件和用户目录做 `<app>`、`<user-data>` 归一化。
- 注册表读取失败不会阻止启动，只在诊断状态中报告。
- 模板自检失败阻止生成，但保留关于/诊断入口和日志访问。
- 签名失败阻止发布压缩步骤，不能把未签名产物误报为已签名。

## 测试与验收

- HEIC 和 HEIF 样本可加入并生成 RGB JPEG；损坏样本给出安全错误。
- 同一路径、不同路径但相同内容、大小相同但内容不同三类去重行为均有测试，顺序稳定；哈希期间窗口保持响应，新批次排队，单个读取失败不阻止其余文件添加。
- 模板打开发生在图片 future 完成前；Word 对象的 prepare/export 线程 ID 相同。
- 轮转达到阈值后产生备份且最多保留 3 个；日志目录回退测试继续通过。
- 主线程和后台线程未捕获异常都被记录，当前任务登记的敏感值和用户目录在日志/提示中被脱敏。
- 模板缺失、损坏 ZIP、缺少文本占位符、缺少/多出图片占位符均被深度检查识别；真实 1～30 模板全部通过。
- 已注册但路径过期时自愈；未注册、非 Windows、开发态不产生注册表写入。
- 设置跨窗口实例恢复；不保存图片列表；清空和成功后的保存规则一致。
- 拖入、拖离、放下、无效文件四条路径都恢复高亮和状态；按钮仍可键盘访问。
- 诊断文本包含版本、Python、HEIF、模板、日志、打包和右键状态，不含表单或图片信息。
- CI 测试 job 先于 build；无证书跳过签名，有证书时只签 `PGT.exe` 并验签；临时 PFX 和导入证书始终删除。
- 新构建不超过 130 MiB，且生成体积报告；若超过则保留报告并阻止发布。
- 全量 pytest、`compileall`、1/10/30 张真实模板集成、PyInstaller 构建和包内启动烟测通过。

## 留给实施者的选择

- 诊断对话框内部控件的精确尺寸可沿用现有 4/8/12/16 间距节奏调整，但不得改变主窗口最小可用高度到需要滚动。
- 体积排除项必须由构建产物和启动/功能烟测证明；任何会削弱远程桌面或无 GPU 兼容性的 Qt 组件不删除。
- 如果 `pi-heif==1.4.0` 在 PyInstaller hook 上暴露问题，先记录证据并修正收集配置，不回退到外部命令行转换器或手工删减 libheif 的静态依赖。
